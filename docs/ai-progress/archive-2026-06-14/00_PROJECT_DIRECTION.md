# 肥猫咖啡公司 大方向推进计划书

更新时间：2026-06-08

## 1. 项目定位

《肥猫咖啡公司》最终形态是一款竖屏移动端联网经营游戏：

- 客户端：Cocos Creator 3.8.8 + TypeScript。
- 服务端：C# / .NET Core，后续提供账号、存档、好友、互动、排行榜、商店校验、活动配置等能力。
- 类型：放置经营 + 猫咪收集养成 + 多层咖啡工厂升级 + 商店背包研究 + 好友互动 + 轻弹射玩法。
- 核心视觉目标：持续向项目根目录 UI 参考图靠拢，而不是停留在灰盒或普通网页式面板。

## 2. 当前项目状态

项目根目录：`D:\Desktop\FATCATCOM`

客户端工程：`D:\Desktop\FATCATCOM\FATCATUI`

关键 UI 参考图：

- `D:\Desktop\FATCATCOM\主页面.png`
- `D:\Desktop\FATCATCOM\所有猫咪页面.png`
- `D:\Desktop\FATCATCOM\猫咪详情页面.png`

当前已具备：

- 配置读取：`ConfigManager` 可读取 `buildings/cats/items/research/shops/skills/tasks/initialSave`。
- 本地存档：`SaveManager` 使用 `localStorage`，当前存档版本 `SAVE_VERSION = 1`。
- 业务系统雏形：资源、建筑、猫咪、生产、商店、背包、研究、任务、技能。
- 主 UI 快速实现：`BottomNavUI.ts` 通过 DOM overlay 快速复刻主界面、底部导航、猫咪详情、建筑、商店、背包、研究、任务等页面。
- 已生成内嵌素材：`GeneratedUiAssets.ts` 中包含主工厂剖面、猫咪详情背景、猫咪头像等 Data URI。

当前主要风险：

- `BottomNavUI.ts` 已超过 2000 行，包含大量 DOM/CSS/业务转发，后续必须逐步拆分，否则维护成本会迅速失控。
- 当前 UI 仍是“快速推进版”，视觉有方向但距离目标图仍有明显差距，尤其是主工厂楼层细节、猫咪总览页、商店/背包/研究的质感和素材丰富度。
- 当前存档和经济逻辑完全在客户端，本地可改，不适合多人联网最终形态。
- 还没有服务端工程、网络协议、账号体系、服务端权威存档和多人互动模型。

## 3. 总体推进原则

1. 先把客户端 UI 做到接近目标图，再进入服务端主线。
2. UI 推进时优先复刻参考图的布局、层级、视觉语言和交互状态。
3. 缺少图片素材时，直接使用 Codex 图片生成能力生成，保存到本地可追踪目录，并嵌入 Cocos UI。
4. 业务逻辑继续保持配置驱动，避免把数值写死在 UI。
5. `BottomNavUI.ts` 只能作为过渡层，后续要拆成面板渲染器、组件、样式/资产管理器。
6. 服务端阶段采用 .NET Core，客户端逐步从本地存档切换为“本地缓存 + 服务端权威”。
7. 每次开发完成后必须更新本目录下计划和 task 文件，让下一次 AI 可以接着做。

## 4. 分阶段路线

### P0：计划与项目记忆固化

目标：建立可持续开发的 AI 计划体系。

状态：进行中。

产物：

- `docs/ai-progress/00_PROJECT_DIRECTION.md`
- `docs/ai-progress/01_DETAILED_PLAN.md`
- `docs/ai-progress/02_TASKS.md`
- `docs/ai-progress/03_UPDATE_RULES.md`

### P1：客户端 UI 目标图复刻

目标：所有主要页面达到目标图 70%-85% 观感。

优先级：

1. 主工厂页：多层建筑、HUD、左右按钮、底部按钮、底部导航、移动端适配。
2. 猫咪总览页：按 `所有猫咪页面.png` 做完整页面或全屏弹层。
3. 猫咪详情页：按 `猫咪详情页面.png` 做完整详情/弹窗。
4. 建筑、商店、背包、研究、任务：按 `其他页面.png` 做风格统一。
5. 全局资源栏、按钮、面板、图标统一。

### P2：客户端架构整理

目标：把快速 DOM overlay 逐步整理成可维护 UI 架构。

方向：

- 拆分 `BottomNavUI.ts`。
- 提取 UI 状态、面板渲染、样式、输入处理。
- 建立素材注册表，统一加载本地 PNG/WebP 和生成素材。
- 为关键交互添加可重复验证脚本。

### P3：玩法闭环补齐

目标：从“页面能点”进入“游戏可玩”。

范围：

- 离线收益、订单系统、任务活跃宝箱。
- 猫咪升级、喂养、技能、装备、皮肤、故事。
- 建筑升级、排班、外观皮肤。
- 商店限购、背包使用、碎片合成。
- 研究树前置和全局加成。
- 发射猫咪玩法 MVP。

### P4：服务端基础工程

目标：创建 .NET Core 服务端，先支持本地/局域网多人可联网运行。

建议技术：

- .NET 8 或 .NET 9 ASP.NET Core Web API。
- Entity Framework Core。
- SQLite 起步，后续可换 PostgreSQL。
- SignalR 用于实时好友互动、在线事件和轻量多人消息。
- JWT 或开发期 Guest Token 账号体系。

服务端首批能力：

- 账号/游客登录。
- 玩家资料。
- 服务端权威资源和存档。
- 配置版本下发。
- 保存同步。
- 好友列表。
- 好友工厂快照。
- 弹射互动请求和结算。

### P5：联网客户端改造

目标：客户端接入服务端，同时保留离线体验。

方向：

- 新增 `NetworkManager`、`ApiClient`、`SyncManager`。
- 本地存档变成缓存，关键资源/购买/互动由服务端确认。
- UI 支持同步中、失败重试、离线模式提示。

### P6：多人互动和运营化

目标：游戏具备可长期扩展的联网玩法。

范围：

- 好友访问和留言。
- 弹射猫咪攻击/偷取/协助。
- 排行榜。
- 邮件和系统奖励。
- 活动商店、限时礼包。
- 管理后台或配置热更新。

## 5. 素材生成策略

素材优先级：

1. 已有目标图和工程素材。
2. 使用 CSS/组件绘制的小图标。
3. 使用 Codex 图片生成能力生成本地 PNG/WebP。

生成素材保存建议：

```text
FATCATUI/assets/resources/textures/generated/
  factory/
  cats/
  ui/
  items/
  backgrounds/
```

每次生成素材必须记录：

- 目标用途。
- prompt 简述。
- 输出路径。
- 是否已接入 UI。
- 视觉验证结果。

记录位置：`docs/ai-progress/02_TASKS.md` 的素材任务，必要时同步 `AI_WORK_LOG.md`。

## 6. 验收基线

客户端 UI 阶段每次提交前至少验证：

- TypeScript 针对相关文件无错误。
- `http://localhost:7456/` 能打开。
- 底部导航至少抽查 2-3 个入口。
- 手机尺寸至少抽查 390x844 或等价竖屏。
- 浏览器 console 无新增关键错误。

服务端阶段每次提交前至少验证：

- `dotnet build` 通过。
- 核心 API 有最小自动化测试或可复现 curl/http 文件。
- 数据库迁移可运行。
- 客户端能在服务端开关关闭时继续本地模式。
